| ar | العربية | **RTL** | zh | 简体中文 | LTR |
| ur | اردو | **RTL** | fil | Filipino | LTR |

People can also pick from **55 spoken languages** for matching, independent of the interface language.

## How it works

- **Detection**: the first supported language in the browser's preference list (`navigator.languages`), with common
  aliases (`zh-*` → zh, `tl` → fil, legacy `in` → id). The user's choice is remembered.
- **Strings**: `public/locales/<code>.json`, one flat key → text map. Missing keys fall back to English.
- **Placeholders**: `{name}`, `{n}`, `{country}`, `{langs}`, `{list}`, `{time}`, `{total}`, `{link}`. Keep every placeholder
  exactly once; word order is free.
- **Country and language names are not translated by hand.** `Intl.DisplayNames` produces them in the user's
  language for all 201 countries and 55 languages. Search matches both the localised and the English name.
- **Numbers, lists and dates** use `Intl.NumberFormat`, `Intl.ListFormat` and `Intl.DateTimeFormat`.
- **Right-to-left**: `<html dir="rtl">` is set for Arabic and Urdu. The CSS uses logical properties
  (`inset-inline-start`, `padding-inline`, `text-align: start`), so the layout mirrors automatically; directional icons
  (back, send) flip.
- **Mixed-direction text**: chat messages and names use `dir="auto"` / `unicode-bidi: plaintext`, and user names
  inserted into translated sentences are wrapped in Unicode isolates (FSI…PDI), so an English name inside an Arabic
  sentence renders correctly.
- **Typography**: negative letter-spacing is turned off for non-Latin scripts (it breaks Arabic joining and hurts
  Indic, Thai and CJK). Non-Latin scripts fall back to system fonts such as Noto, Segoe UI, Hiragino and PingFang.
- **Interests** are canonical ids with translated labels, so people match on interests across languages.

## Adding a language

1. Copy `public/locales/en.json` to `public/locales/<code>.json` and translate the values. Keep the keys.
2. Add the language to `UI_LOCALES` in `shared/data.js`: `['sw', 'Kiswahili', 'ltr']` (use `'rtl'` for
   right-to-left scripts such as Persian or Hebrew).
3. If it's a Latin-script language, add the code to the `LATIN` set in `public/js/i18n.js` (enables tighter headline
   letter-spacing).
4. Run `npm test`. The locale tests fail on any missing key, extra key, empty value or changed placeholder.

## Style guide for translators

- Friendly and direct, like texting a friend. Use the informal "you" where the language has one (tú, du, tu, ты,
  kamu), except where formal is the norm for apps in that market (e.g. Hindi आप, Japanese です/ます).
- Buttons say what happens: "Start video chat", "Block", not "OK" or "Submit".
- Keep the brand "Dunia" in Latin letters.
- `onb.age` contains `{link}`, which becomes the linked text of `legal.guidelines`. Make sure the sentence reads
  naturally with that term inserted (Turkish, for example, uses "…kabul ediyorum: {link}.").
- Report reasons are read under stress: short and unambiguous beats elegant.
- Some translations are machine-quality starting points. Have a native speaker review each language before
  launching in its market, especially the safety and legal strings.
